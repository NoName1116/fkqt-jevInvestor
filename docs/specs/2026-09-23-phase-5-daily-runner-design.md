# Phase 5 日频运行设计

日期：2026-09-23。需求：R3、R4、R6、R16—R18、R21、R22、R27、R32、R33、R43、R46—R49。

## 目标与边界

外部调度器在 D 日 15:00 后触发 `daily close`。D+1 收盘行情齐备后先触发 `daily execute`，它以 D+1 开盘价回放虚拟成交、以收盘价更新 NAV；再触发 D+1 的 `daily close`。因此这不是开盘即时下单器。程序不连接券商、不常驻运行、不自动补下单。交易日历仍由 D 日冻结快照给出；调度器只负责唤醒，不决定 D+1 日期。

```text
FKQT 不可变 Manifest ──> D 日冻结快照/特征 ──> Jev ──> DeepSeek ──> 虚拟订单
       |                                                              |
       └─ D+1 执行行情包 ──> 哈希与覆盖验证 ──> 虚拟成交/持仓/NAV <────────┘
                                      |
                         CLI 状态、退出码、外部监控
```

## 输入输出

| 阶段 | 输入 | 输出 | 依赖 |
|---|---|---|---|
| `daily close` | 日期、组合、容量、冻结候选列表、Manifest | 市场快照、稳定 run_id、C 组信号及虚拟订单 | Phase 2—4、两个 Provider Secret |
| `daily execute` | 日期、组合、执行行情包路径 | 成交、终态订单、组合快照及 NAV | Phase 1 执行引擎 |
| `daily status` | 日期、组合 | JSON 状态和监控字段 | 本地数据库 |

执行行情包的 `content_hash` 用除该字段以外的规范 JSON 计算 SHA-256。每个证券使用现有 `MarketExecutionSnapshot` 结构。包只能表示一个交易日，证券键与内部 `symbol` 必须一致。执行前必须覆盖当前持仓和到期订单；没有订单也必须完成持仓估值。包原始文件保留在受控 `data/` 路径，由上游发布，不让 CLI 修改原件。

## 幂等与恢复

稳定 run_id 由组合、日期、快照 hash、候选池、容量和组合版本生成。冻结文件采用现有内容寻址保存；Jev、决策和信号使用现有正式键与唯一约束。执行使用 `portfolio_id + trade_date` 唯一 NAV；重复调用返回已有结果。任意阶段失败时退出非零，不继续下一阶段；修复外部条件后用同一命令重跑。若正式模型结果已落库，重跑只能复用，不因网络恢复改写历史。

## 风险与验收

- 运行前的时间门禁拒绝 D 日 15:00 之前的正式收盘调用。
- 执行日期必须与 D 日信号的 `planned_execution_date` 一致；无订单的估值日允许执行。
- 股票缺失、包 hash 不匹配、错日、组合版本冲突均须拒绝，不能部分成交。
- `daily status` 不读取 API Key；任务调度器用退出码和 JSON 进行外部告警。
- 沙耶的 `backtest/` 契约与实现不在 Phase 5 修改范围。

## 已知限制

执行行情包由外部 FKQT 导出，本阶段不实现 FKQT 新接口；因此没有可信包时不能运行真实前向执行。CLI 自身不提供 SMS、邮件或 Web 告警。模型终态失败按 Phase 4 规则保持 `NO_SIGNAL`，不得自动换模型重评。
